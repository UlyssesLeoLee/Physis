# Archived: Physical Retrieval Engine（PRE）documentation

**Status: SUPERSEDED.** These 13 documents (01–12 plus the diagram set) described an earlier
project direction — PRE, a retrieval-first runtime that indexed physics experiences generated by
pluggable third-party-style solvers, deliberately avoiding self-developed core physics solving
(`NG3: 不自研全部 solver`).

That direction has been replaced by **GVPE (Graph-Governed Vector Physics Engine)**, documented at
the repository root of `docs/` (`00_vision.md` onward). GVPE inverts the priority: a fully
self-developed Rust physics solver is the mandatory core, with the knowledge graph and vector space
acting as an offline/low-frequency control plane that compiles down to runtime parameters — never
as a hot-path dependency.

Key incompatibilities that made "extend PRE" infeasible instead of "replace PRE":

- PRE's ADR-006/013 explicitly rejected embedding a graph database; GVPE requires evaluating and
  embedding one (as a Control Plane store, not a Data Plane one) under strict license review (§16).
- PRE's solver strategy was plugin-first, treating solvers as replaceable, non-core components; GVPE
  requires an authoritative self-developed solver core, with any third-party engine research treated
  as prior-art reading only, never as a wrapped runtime.
- PRE's core index object was the "Physical Response" retrieved via vector search with the solver as
  incidental; GVPE's core is the real-time solver itself, with retrieval/graph as an optional
  reasoning layer that can be fully disabled without breaking the runtime.

Kept for historical reference and to preserve the IPA-style documentation conventions (revision
history tables, requirement ID traceability, ADR structure) that GVPE's documents continue to follow.
Do not build against this archived spec.
